## Key Question 1 — Which Rhino / Grasshopper MCP servers exist? (inventory)

### Takeaway
As of October 2026 there are roughly 20 Rhino/Grasshopper MCP bridges on GitHub plus several Food4Rhino listings. Two dominate: McNeel's **official "Rhino MCP Platform" (repo mcneel/RhinoAI, MIT, 358 stars, last commit 2026-10-06)** and the community **jingcheng-chen/rhinomcp (MIT, ~1.1k stars, last commit 2026-09-13, v0.4.1.1)**. For Grasshopper the most active dedicated servers are **Cordyceps (brookstalley, 105 stars, v1.5.0 2026-08-29)** and **LAMCP (ETH Gramazio Kohler, v0.5.0)**. The oldest widely-listed ones (alfredatnycu/grasshopper-mcp, SerjoschDuering/rhino-mcp, a01110946/RhinoMCP) have been dormant since spring 2025.

### Inferences
- The field has consolidated around two "serious" general-purpose servers (McNeel official and jingcheng-chen), both MIT, both Rhino 8 Windows+Mac, both with Grasshopper tooling, both updated within the last 4–5 weeks. Everything else is either narrowly scoped (Cordyceps/LAMCP for Grasshopper), Windows-only (tanishqbhattad), macOS-leaning (GOLEM), brand-new (MCP4Rhino, 4 days old), or dormant since 2025 (alfredatnycu, SerjoschDuering and its forks, a01110946, always-tinkering).
- Many directory sites (mcp.so, glama, playbooks, lobehub, PulseMCP-style) re-list the same blender_mcp-derived forks under the name "RhinoMCP", which inflates the apparent count; the lineage SerjoschDuering → sholtomaud/mustafaisildakcom/Archolic95/reer-ide is one codebase family.
- The official plugin's 0.3.0 rewrite "from Python to C#" (Sept 30, 2026) and the "Moved down… to version 8.19" note imply the minimum Rhino 8 service release is 8.19 for the current official plugin.

## Key Question 2 — Has McNeel released or endorsed an official MCP server / Claude integration / LLM assistant (2025–2026)?

### Takeaway
Yes. McNeel ships an official, MIT-licensed "Rhino MCP Platform" (repo mcneel/RhinoAI; Yak package `Rhino-MCP-Platform`) with a Claude Desktop connector, documented Claude Code setup, a Rhino 8 plugin, and GH1/GH2 tools; since Sept 30, 2026 it also includes a built-in **AI Panel** (`AIPanel` command) that is in Rhino 9 BETA by default and installable in Rhino 8 via Package Manager, currently supporting Claude and Codex as backends. Officially it is still beta-quality (version 0.3.0 plugin / 0.1.6 connector), with known rough edges around ports, Claude Desktop's Connectors UI and Intel Macs.

### Cited Findings

## Key Question 4 — Which work with Claude Code (CLI) vs only Claude Desktop? Can a cloud-hosted Claude Code session reach a desktop Rhino (tunnel), or is it strictly local?

Every design is local-first (loopback), but the servers that speak **Streamable HTTP** (McNeel official plugin, Cordyceps :26929, MCP4Rhino :4010, 4kk11 :3001, EaseHee) are the ones that can in principle be exposed through a tunnel; only EaseHee documents a tunnel/claude.ai-remote-connector setup, and McNeel's server was reportedly changed to accept remote connections in late summer 2026. ### Inferences
- For a *local* Claude Code CLI on the same machine as Rhino 8, the official platform and jingcheng-chen both work with a one-line setup; Cordyceps adds Grasshopper.

## Key Question 6 — Non-MCP agent approaches used with Rhino + Claude (for comparison)

### Takeaway
The practical alternatives are: (1) Claude writes Python 3 (CPython 3.9) or C# for the Rhino 8 **ScriptEditor**, run manually or via `_-ScriptEditor _R "file.py"`; (2) **rhino3dm** to generate `.3dm` files with no Rhino running (and EaseHee's standalone mode wraps this as MCP); (3) **Rhino.Compute** REST for geometry ops; (4) Claude Code **skills** that teach it to build compiled `.gha`/`.rhp` plug-ins; (5) Claude generating `.gh` files via a Python script; (6) screen-based computer use.

### Cited Findings
- Rhino 8 ScriptEditor: "Run the ScriptEditor command… Choose File > New and pick Python 3"; can run a saved file "from the command line, a macro, a toolbar button, or an alias (`_-ScriptEditor _R "C:\path\to\script.py"`)"; "Rhino 8 uses Python version 3.9.11"; "unified Script Editor with debugging in Rhino and Grasshopper, with Python 3 (CPython) supporting… PyPI packages" (via search summaries) — [developer.rhino3d.com scripting-python](https://developer.rhino3d.com/guides/scripting/scripting-python/), [rhino3d.com scripting](https://www.rhino3d.com/features/developer/scripting/)
- RhinoCommon is "only available in Rhino's embedded Python (or via rhino3dm for read-only file work)"; outside Rhino "No module named Rhino" (via search summary) — [rhino3d-scripts skill listing](https://awesome-copilot.github.com/skill/rhino3d-scripts/); the same skill is listed for agents — [mcpservers.org](https://mcpservers.org/agent-skills/github/rhino3d-scripts)
- Rhino.Compute: "rhino3dm.py as a Python wrapper for OpenNurbs that reads and writes Rhino geometry objects. The companion compute-rhino3d package makes calls into the McNeel Cloud Compute server" (via search summary) — [compute-python-getting-started](https://developer.rhino3d.com/guides/compute/compute-python-getting-started/)

### Inferences (incl. fit for the maze-fabrication workflow)
- For a cloud Claude Code session with no tunnel, the zero-infrastructure path is: Claude Code writes a Python 3 script (rhinoscriptsyntax/RhinoCommon) that ingests the maze app's SVG/JSON, builds polylines per named layer (boundary/walls/solution/dead-end-N), extrudes/offsets for CNC or 3D print, and exports (DXF/STEP/STL/3DM) — the user runs it once in Rhino 8's ScriptEditor. The same script can later be executed through any MCP server's Python-execution tool (jingcheng-chen `execute_rhinoscript_python_code`, McNeel `run_python`, tanishqbhattad `execute_python3`, reer-ide `execute_code`) with no rewrite.
- rhino3dm (pure Python, no Rhino) could produce `.3dm` files with layers and curves/extrusions directly from the cloud; fine for curves and simple extrusions, but booleans/filleting require Rhino or Rhino.Compute.
- A Rhino 7 user would have almost no MCP options (official and jingcheng-chen are Rhino 8 only; only the dormant 2025 forks and RhinoAiMCP claim Rhino 7); the user's Rhino 8 license is the right generation.
