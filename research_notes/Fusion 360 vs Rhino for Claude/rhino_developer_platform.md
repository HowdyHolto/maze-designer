## 1. RhinoCommon .NET SDK and Rhino 8 scripting (C#, CPython 3, IronPython 2)

### Takeaway
Rhino 8 ships a unified ScriptEditor (Windows and Mac, since 8.0) that runs CPython 3 (a 3.9 runtime under `~/.rhinocode/py39-rh8`), legacy IronPython 2.7 and modern C#, all against the RhinoCommon .NET API; Python 3 scripts declare pip dependencies inline (`#r: numpy`, `#requirements:`, PEP 723 blocks) and Rhino installs them itself. Everything in this section requires a licensed, running Rhino GUI process (there is no headless desktop mode), but a terminal agent on the same machine can drive it through documented macros and the `rhinocode` CLI (see section 5).

### Cited Findings
- The ScriptEditor is "a place you write scripts to customize" Rhino; platforms Windows and Mac; available since Rhino 8. Rhino 7 and earlier offered C#, IronPython, RhinoScript, VB and GHGL; new in Rhino 8: a unified editor, Python 3, modern C#, improved IronPython, "no more vb", GHGL "in progress", libraries and easier script sharing — [What is ScriptEditor (developer.rhino3d.com guide; read from source repo)](https://developer.rhino3d.com/guides/scripting/what-is-scripteditor/)
- McNeel's Python guide states Rhino supports "IronPython 2.7, and CPython 3.9", described as the Python executables embedded in Rhino that the ScriptEditor uses (search snippet) — [What is Rhino.Python?](https://developer.rhino3d.com/guides/rhinopython/what-is-rhinopython/)
- The Rhino 8 scripting feature page says Python 3 and .NET scripting share "a common editor in Grasshopper and Rhino on both Windows and Mac", with CPython + PyPI packages and C# + NuGet packages; the Rhino 7 tools (IronPython 2.7, C#/VB.Net components) remain as legacy options (search snippet) — [rhino3d.com Scripting feature page](https://www.rhino3d.com/features/developer/scripting)
- Runtimes live under `%USERPROFILE%\.rhinocode` (Windows) / `~/.rhinocode` (macOS); Python 3 in Rhino 8 is at `~/.rhinocode/py39-rh8/` (and IronPython at `py27-rh8`). On first use "Python 3 prepares its runtime and installs a few useful pip packages"; Python 3 "needs to run Python executive binary" to start the language server and install packages from PyPI.org. The root can be moved with the `RhinoCodePlugin.RootPath` advanced option — [Language Initialization guide](https://developer.rhino3d.com/guides/scripting/advanced-langinit/)
- Python 3 is CPython and reaches RhinoCommon through Python.NET; Python 2 is IronPython running on .NET with "real .NET multithreading" and faster pure-RhinoCommon calls; the guide calls Python 3 "the better starting point for most scripts". A script beginning with `#! python 3` / `#! python 2`, or saved as `.py3` / `.py2`, is tied to that runtime. Engines can be restarted via Tools > Reload Python 3 (CPython) Engine — [Scripting in Python guide](https://developer.rhino3d.com/guides/scripting/scripting-python/)
- Package directives (Python 3): `#r: numpy`, `#requirements: numpy, requests`, pip version specifiers (`#r: torch==2.4.1`, `#r: numpy>=1.2`), full form `#r "pip: numpy"`, editable local libraries `#r "pip: --editable /Users/me/dev/mylibrary"`, Git pins `#r "pip: git+https://github.com/user/repo.git@9e3c1a2"`, pip options `--index-url`, `--extra-index-url`, `--find-links`, `--no-index`; PEP 723 `# /// script` blocks are read but only the `dependencies` list is honoured. C#: `#r "nuget: RestSharp, 110.2.0"`; Yak packages `#r "yak: LunchBox, 2025.5.5"`; assemblies `#r "System.Text.Json.dll"`. "Python 2 has no pip" — only `#wheel: /path/to/package.whl` — [Packages & Libraries guide](https://developer.rhino3d.com/guides/scripting/advanced-packages/)
- The ScriptEditor command guide also documents `#env: C:/Path/To/Where/My/Library/Is/Located/` for adding a local library path, and states IronPython is limited to packages it supports — [ScriptEditor command guide](https://developer.rhino3d.com/guides/scripting/scripting-command/)
- Forum reports: the `# r:` line must precede the `import`; running `pip install` in a system terminal does not make packages visible because Rhino "uses a custom deployment of python"; one user reports `# r:` and `# env:` are ignored when placed in an imported module rather than the top-level script (unresolved) — [Discourse: ScriptEditor Requirements and Path](https://discourse.mcneel.com/t/scripteditor-requirements-and-path/211266); [Discourse: How to implement Python 3 modules in Rhino 8](https://discourse.mcneel.com/t/how-to-implement-python-3-modules-in-rhino-8/170436/2); [Discourse: Rhino 8 Feature: ScriptEditor (CPython, CSharp)](https://discourse.mcneel.com/t/rhino-8-feature-scripteditor-cpython-csharp/128353)
- The legacy IronPython-only editor is still reachable via `EditPythonScript`; the new editor opens with `ScriptEditor` (search snippet) — [Discourse: Rhino 8 scripts](https://discourse.mcneel.com/t/rhino-8-scripts/165657)
- Script projects (`.rhproj`) can be built into a `.rhp` Rhino plugin, `.gha` Grasshopper plugin, `.rui` toolbar and `.yak` package by `rhinocode project build`, which "doesn't require a running Rhino instance, so it works in CI/CD pipelines" — [RhinoCode CLI guide](https://developer.rhino3d.com/guides/scripting/advanced-cli/)
- Rhino 8 desktop requirements: Windows 10/11 or macOS 12.4+; Linux and Windows Server are excluded (search snippet) — [Rhino 8 System Requirements](https://www.rhino3d.com/8/system-requirements)

### Inferences
- For a Claude Code agent sitting next to Rhino, the practical pattern is: write a `.py` file beginning with `#! python 3` plus `#r:` lines, then trigger it with `rhinocode script <file>` or the `_-ScriptEditor _R "<path>"` macro (section 5). Package installation happens inside Rhino's private CPython 3.9, so the agent must not expect its own venv/`pip` to be visible to Rhino.
- CPython 3.9 is end-of-life upstream (Oct 2025), so modern wheels (numpy 2.x, shapely 2.1, etc.) may stop publishing cp39 builds; that is a real risk for `#r:` dependencies in Rhino 8. (Inference — McNeel has not announced a Rhino 8 Python bump in anything I found.)
- Nothing in this section runs in a Linux container; the SDK requires a running, licensed Rhino.

### Gaps
- Exact patch version of the embedded CPython (guides say only `py39`) and whether Rhino 9 Beta moves to a newer CPython — not found (the Language Initialization guide covers Rhino 8 only).
- No official statement located on `rhinoscriptsyntax` availability in Python 3 (the Python guide does not mention it); the full `advanced-pyruntime` guide was an empty stub in the repo.
- The .NET version used by Rhino 8 C# scripts was not stated in the pages I could read (Rhino.Inside.CPython README lists `net48`, `net7.0`, `net8.0`, `net9.0` targets for Rhino 8/9, see section 4).

## 2. rhino3dm (open-source .3dm read/write without Rhino)

### Takeaway
rhino3dm is McNeel's MIT-licensed, actively maintained openNURBS wrapper for Python (pip, CPython 3.9–3.14, Windows/macOS/Linux incl. aarch64), JavaScript/WebAssembly (npm, browser and Node) and .NET (NuGet); version 8.35.0 was published to both PyPI and npm on 15 Sep 2026. It can author full `.3dm` files — points, curves (NURBS/polylines), surfaces, Breps, extrusions, meshes, SubDs, annotations, hatches, layers, groups, materials, object attributes/user data — but it is geometry *storage and interrogation* only: intersections, booleans, meshing of Breps, closest-point and mass properties are explicitly listed by McNeel as the things openNURBS lacks and Rhino.Compute adds. This is the only McNeel mechanism that runs in a Linux container with no Rhino licence.

### Cited Findings
- Description: "a set of geometry libraries based on the OpenNURBS library, with a RhinoCommon-style API"; works "independent of Rhino". Python: CPython 3.8–3.14 on Windows, macOS, Linux; JavaScript: WASM build for major browsers and Node.js; .NET: NuGet `Rhino3dm` for macOS/Windows/Linux. Capabilities: "Create, interrogate, and store" points, point clouds, NURBS curves and surfaces, polysurfaces (B-Reps), meshes, annotations, extrusions, SubDs; "non-geometry classes such as layers, object attributes, transforms, and viewports"; "Read and write .3dm files"; "Act as a client for the Rhino Compute cloud server for more advanced geometry operations". Repo stats at read time: 764 stars, 155 forks, MIT, 2,629 commits on the `9.x` branch, 16 open issues; GitHub Releases tab empty ("There aren't any releases here") — [github.com/mcneel/rhino3dm](https://github.com/mcneel/rhino3dm); [rhino3dm Releases page](https://github.com/mcneel/rhino3dm/releases)
- PyPI (registry JSON, 11 Oct 2026): latest 8.35.0 uploaded 2026-09-15; `requires_python >=3.9`; licence MIT; summary "Python library based on OpenNURBS with a RhinoCommon style"; 35 files in the release incl. wheels for cp39–cp314 on `win_amd64`, `win_arm64` (cp311+), `macosx_14_0_universal2`, `macosx_15_0_universal2`, `manylinux_2_27_x86_64.manylinux_2_28_x86_64`, `manylinux_2_27_aarch64.manylinux_2_28_aarch64`, plus sdist. Recent cadence: 8.32.0 (2026-07-28), 8.32.1 (2026-08-24), 8.35.0b1/b2 (Aug 2026), 8.35.0 (2026-09-15); before that 8.17.0 (2025-03-12) — [pypi.org/project/rhino3dm](https://pypi.org/project/rhino3dm/)
- npm (registry JSON): `latest` 8.35.0 published 2026-09-15; `next` 8.35.0-beta1; 8.32.2 (2026-08-18); licence MIT; "Node.js package based on OpenNURBS with a RhinoCommon style" — [npmjs.com/package/rhino3dm](https://www.npmjs.com/package/rhino3dm)
- Python docs: `pip install rhino3dm --user`; wheel matrix listed (Windows 64-bit 3.7–3.13, macOS 13 Homebrew, macOS 14/15 universal, Linux manylinux_2_28 x86_64 and aarch64, others via sdist — this page lags the registry, which already has cp314); the only example creates an `Arc`, converts `ToNurbsCurve()` and reads `PointAtStart`; API docs at mcneel.github.io/rhino3dm/python/api — [RHINO3DM.PY.md](https://github.com/mcneel/rhino3dm/blob/main/docs/python/RHINO3DM.PY.md)
- JavaScript docs: load with `import rhino3dm from 'rhino3dm'; const rhino = await rhino3dm()` in browser (import map to jsDelivr) or Node (`npm install rhino3dm`); self-hosting needs the `.wasm` next to the `.js`; the WASM binary is "fairly large for browser based applications"; the sample 3dm viewer reads files locally but "calls compute.rhino3d.com" to create meshes and isocurves — [RHINO3DM.JS.md](https://github.com/mcneel/rhino3dm/blob/main/docs/javascript/RHINO3DM.JS.md)
- Generated Python API class list (visible portion) includes `File3dm`, `File3dmLayerTable`, `File3dmObjectTable`, `File3dmGroupTable`, `File3dmInstanceDefinitionTable`, `File3dmMaterialTable`, `File3dmDimStyleTable`, `File3dmStringTable`, `File3dmWriteOptions`, `Layer`, `Brep`, `Extrusion`, `Mesh`, `NurbsCurve`, `LineCurve`, `ArcCurve`, `Hatch`, `InstanceDefinition`, `InstanceReference`, `Material`, `Intersection`, `ArchivableDictionary`, `DimLinear`, `Leader`, `Group`, `Light`, `Linetype`, `MeshingParameters` — [rhino3dm docs/python/api listing](https://github.com/mcneel/rhino3dm/tree/main/docs/python/api)
- McNeel's Rhino.Compute feature page says Compute "adds functions missing from openNURBS, including closest point, intersection, meshing, interpolation, booleans, and area/mass properties" — i.e., the official list of what rhino3dm/openNURBS cannot do on its own — [Rhino.Compute Features guide](https://developer.rhino3d.com/guides/compute/features/)
- A McNeel developer on the forum: openNURBS "does not have all of the capabilities of Rhino", hence rhino3dm differs from RhinoCommon; use RhinoCommon inside Rhino and rhino3dm when working independently of Rhino (search snippet) — [Discourse: Using Rhino3dm and RhinoCommon for Development](https://discourse.mcneel.com/t/using-rhino3dm-and-rhinocommon-for-development/156161)
- In rhino3dm Python, `File3dm.Objects.Add(geometry, attributes)` takes a geometry plus an `ObjectAttributes` object (search snippet of a user thread) — [Discourse: Rhino3dm Python Add object to File3dmObjectTable](https://discourse.mcneel.com/t/rhino3dm-python-add-object-to-file3dmobjecttable/91785); user-string (user text) read/write on objects via rhino3dm.py is discussed (with a historical read-back bug) in [Discourse: Rhino3dm.py can't read object user strings](https://discourse.mcneel.com/t/rhino3dm-py-cant-read-object-user-strings-from-existing-file/108245)
- rhino3dm has a dedicated forum category — [Discourse: About the rhino3dm category](https://discourse.mcneel.com/t/about-the-rhino3dm-category/73326)

### Inferences
- For the maze app, rhino3dm is the natural "Linux-container, no-Rhino" path: an agent can translate the SVG's named layers into `File3dm` layers (`Layer` objects added to `file.Layers`, objects assigned by layer index through `ObjectAttributes`), write wall centre-lines as `PolylineCurve`/`NurbsCurve`, closed boundary curves, and even `Extrusion` solids (a planar closed curve extruded by the wall height) — all of which are supported types in the API listing. It cannot offset curves into wall thickness, boolean-subtract paths from a slab, or mesh a Brep; those need Rhino itself or Rhino.Compute.
- The project is clearly alive (three releases in Jul–Sep 2026 after a 16-month gap, cp314 wheels, Windows ARM64 wheels). Version numbers track Rhino (8.x) and development has moved to a `9.x` branch, so a 9.x line should be expected alongside Rhino 9.
- Because the published Python docs still list 3.7–3.13 while PyPI already ships 3.14 wheels and requires ≥3.9, treat the registry, not the markdown docs, as truth for version support.

### Gaps
- I could not open the generated API pages (mcneel.github.io blocked), so I could not confirm the exact method names for `ObjectAttributes.SetUserString`/`GetUserString`, `Layer.Color`, or `File3dm.Write(path, version)` — the class listing was truncated after `NurbsCurveKnotList`; `ObjectAttributes`, `PolylineCurve`, `Transform` were in the hidden remainder. Forum threads above imply they exist.
- The scope of the `Intersection` class in rhino3dm (visible in the API listing) is unverified; openNURBS historically offers only simple analytic intersections (line/line, line/plane), not curve/curve or Brep/Brep — treat as unconfirmed.
- No changelog for 8.32→8.35 could be read (no GitHub Releases; CHANGELOG not fetched).

## 3. Rhino.Compute (headless REST geometry server) and Hops

### Takeaway
Rhino.Compute is McNeel's open-source REST wrapper that runs a headless Rhino (via Rhino.Inside) and exposes "2400+" RhinoCommon calls plus Grasshopper-definition evaluation; it is Windows-only for production (a WIP Linux build exists, tested on Ubuntu 24.04 / Amazon Linux 2023), never macOS. On a desktop Windows PC it runs free under the user's ordinary Rhino 8 licence (default `http://localhost:6500`); on any Windows Server or Linux/cloud VM it requires Core-Hour Billing at $0.10 per core-hour (pro-rated per minute, charged for uptime, not calls). The official Python/JS client packages on PyPI/npm date from 2020–2021.

### Cited Findings
- "REST API for RhinoCommon and Grasshopper"; "Compute is built on top of Rhino 8 for Windows and can run anywhere Rhino 8 for Windows can run". Repo: 405 stars, 222 forks, 80 open issues, `9.x` branch with 1,757 commits, no GitHub Releases; `src/` contains `compute.geometry`, `rhino.compute`, `hops`, `HopsNetCore`, `ghhops-server-py` — [github.com/mcneel/compute.rhino3d](https://github.com/mcneel/compute.rhino3d); [src listing (8.x)](https://github.com/mcneel/compute.rhino3d/tree/8.x/src)
- FAQ: runs on Windows and Linux; "macOS is not supported"; Linux tested on Ubuntu 24.04 and Amazon Linux 2023; "Rhino.Compute depends on Rhino.Inside"; on a regular Windows PC it checks for a standard Rhino licence at startup (evaluation versions work) and local use has no extra cost; on a Windows or Linux server (e.g. cloud VM) a Core-Hour Billing token in `RHINO_TOKEN` is required; Hops "automatically starts a Rhino.Compute instance when Grasshopper opens" — [Rhino.Compute FAQ](https://developer.rhino3d.com/guides/compute/compute-faq/)
- Core-Hour Billing: "$0.10 per core per hour", pro-rated per minute; "required when running Rhino on a Windows Server-based operating system"; "not compatible with Rhino Educational or Commercial licenses"; the billing team must contain no licences; billing is based on uptime not usage; multiple Rhino instances on one machine cost the same as one; token obtained in Licenses Portal → Manage Team → Manage Core-Hour Billing → Get Auth Token and set as machine-level env var `RHINO_TOKEN` ("Do NOT share this token with anyone") — [Licensing & Billing guide](https://developer.rhino3d.com/guides/compute/core-hour-billing/)
- Development guide: "Rhino.Compute only runs in Windows"; needs Visual Studio 2022, Git, Rhino 8 (branch 8.x) or 7; local base address `http://localhost:6500` with `/version`, `/healthcheck`, `/activechildren`, `/sdk`; `compute.geometry` is the REST geometry layer, `rhino.compute` the service layer handling auth, child-process spawning and idle shutdown; on first start Rhino asks to validate the licence locally or via Cloud Zoo — [Developing with Rhino.Compute](https://developer.rhino3d.com/guides/compute/development/)
- Features: "2400+ RhinoCommon API calls"; adds closest point, intersection, meshing, interpolation, booleans, area/mass properties missing from openNURBS; client libraries for C#(.NET), Python, JavaScript; Grasshopper definitions solved "in serial or parallel"; operations can be serialised in one request via Grasshopper or Python scripts; stateless API; platforms listed Windows and Linux — [Rhino.Compute Features](https://developer.rhino3d.com/guides/compute/features/)
- Linux: "should be considered WIP software. We do not recommend using this for production work"; tested on Ubuntu Server 24.04 and AmazonLinux 2023 (Debian 13 as Docker base, Raspberry Pi 400 tested); requires `RHINO_TOKEN` core-hour token plus a self-chosen `RHINO_COMPUTE_KEY`; installs .NET 9.0.102; container start via `rhino-compute-start` on port 5000; "Only 3dm files are supported for import and export"; "Expect that 3rd party plugins will not work at this time" (only `-any` Yak packages with GH add-ons load); Grasshopper host needs "Rhino 8 or Rhino WIP with Hops" — [Rhino.Compute on Linux getting started](https://developer.rhino3d.com/guides/compute/compute-linux-getting-started/); McNeel forum announcement "Rhino BETA Feature: Rhino.Compute on Linux" — BETA, Ubuntu Server 24.04 and Amazon Linux 2023, "not for production", first developed for Windows servers (search snippet) — [Discourse thread 217111](https://discourse.mcneel.com/t/rhino-beta-feature-rhino-compute-on-linux/217111)
- Python client: `pip install rhino3dm` and `pip install compute-rhino3d` (import as `compute_rhino3d`), described as "a work in progress package" handling auth and JSON conversion; the page still cites Python 2.7/3.7 support (stale); 2400+ calls listed at compute.rhino3d.com/sdk; samples at github.com/mcneel/compute.rhino3d.samples — [Compute: Python getting started](https://developer.rhino3d.com/guides/compute/compute-python-getting-started/)
- Registry facts: PyPI `compute-rhino3d` latest 0.12.2 uploaded 2020-11-27; npm `compute-rhino3d` latest tag 0.13.0-beta published 2021-01-25 — [pypi.org/project/compute-rhino3d](https://pypi.org/project/compute-rhino3d/); [npmjs.com/package/compute-rhino3d](https://www.npmjs.com/package/compute-rhino3d)
- Forum licensing confirmations (Rhino 7-era): local Compute on a desktop uses the standard Rhino licence; calling Compute from another computer, or on a server, moves you to core-hour billing (search snippets) — [Discourse: Licensing of a Local Rhino.Compute Server](https://discourse.mcneel.com/t/licensing-of-a-local-rhino-compute-server/136795); [Discourse: Rhino Compute license](https://discourse.mcneel.com/t/rhino-compute-license/191552)
- Hops: lets you treat separate Grasshopper definitions as functions; the Hops component (client) points at a definition by file path or URL, the "Rhino server" is "a headless (no UI) Rhino and Grasshopper instance"; can optionally point to a Rhino.Compute server on another computer; installed via `PackageManager` ("Hops"); page metadata lists Windows and Mac — [What is Hops](https://developer.rhino3d.com/guides/compute/what-is-hops/). Protocol: Hops bundles the definition into an HTTP request to `/io` (server determines inputs/outputs and stores the definition), then `/solve` sends a pointer ID plus input data; last requests/responses can be exported for debugging — [How Hops Works](https://developer.rhino3d.com/guides/compute/how-hops-works/)
- A McNeel developer: "there is no Rhino.Inside support for Rhino for Mac yet", no timeline, initial effort would be on Hops because a no-UI version is easier; possible Rhino 9 or 10 timeframe (search snippet) — [Discourse: Rhino.Inside on macOS](https://discourse.mcneel.com/t/rhino-inside-on-macos/173311)

### Inferences
- For a user on **Windows**, Rhino.Compute is the strongest "agent-friendly" route: a localhost REST API (JSON in/out) that a Python/Node script — or an MCP server — can call without touching the GUI, and it is free under the existing Rhino 8 licence. Booleans, offsets, meshing and Grasshopper-definition evaluation (`/grasshopper` via Hops endpoints) are all reachable this way.
- For a user on **macOS**, Rhino.Compute is not an option locally; the choices collapse to in-process scripting (section 1/5) or paying core-hour billing on a Windows/Linux cloud VM (~$0.10/core/hr of uptime — e.g. ~$72/month for one always-on core).
- In a Linux CI container without a licence, Compute is only usable against a remote instance that the user pays for; the Linux build additionally cannot import/export anything but `.3dm`, so SVG→Compute→STEP pipelines would still need Windows.
- The official `compute-rhino3d` clients are five years stale; treat them as thin JSON helpers and expect to hand-roll calls against `/sdk`-documented endpoints.

### Gaps
- No Rhino-8-specific change to Compute licensing was found; all licensing statements are version-agnostic or Rhino 7-era.
- Whether the Linux WIP build runs the Rhino 8 or Rhino 9 engine was not stated (only ".NET 9.0.102" and "Rhino 8 or Rhino WIP with Hops" for the GH host).
- No information on request-size limits, timeouts or the exact `/grasshopper` endpoint signature (the `how-hops-works` page covers `/io` and `/solve` only).

## 4. Rhino.Inside and Rhino.Inside.CPython

### Takeaway
Rhino.Inside embeds the full Rhino/Grasshopper engine inside another 64-bit process (Revit, Unity, a console app, CPython); it is Windows-only, needs a licensed Rhino 7/8/9-WIP install on the same machine, and is the technology underneath Rhino.Compute. The `rhinoinside` pip package (0.8.2, June 2025) lets a plain CPython ≥3.7 script `import rhinoinside; rhinoinside.load(8, 'net8.0')` and then use `Rhino.Geometry` directly — the closest thing to "headless Rhino from a terminal", but only on Windows.

### Cited Findings
- "The Rhino.Inside® technology allows Rhino and Grasshopper to be embedded within other products": start Rhino/Grasshopper as an add-in, call host APIs from Rhino/GH plugins, access Rhino APIs through the host, open/preview GH definitions inside the parent process, create objects natively in the host. Samples: "Rhino 8 (dotnet core)" and "Rhino 8" (.NET Framework) in `rhino-developer-samples`. Repo: 416 stars, 186 forks, MIT, branch `rhino-8.x` (988 commits); NuGet package `Rhino.Inside` — [github.com/mcneel/rhino.inside](https://github.com/mcneel/rhino.inside)
- `rhinoinside` PyPI package, latest 0.8.2 uploaded 2025-06-03 (0.7.0–0.8.1 in May 2025; 0.6.0 Aug 2021). Requirements: "Rhino 7, 8, 9 (WIP)", "Windows", "64 bit version of CPython (>= 3.7)". Usage: `pip install --user rhinoinside`; `rhinoinside.load()` (defaults to Rhino 7 on net48); `rhinoinside.load(8, 'net8.0')`, `rhinoinside.load(8, 'net7.0')`, `rhinoinside.load(r"C:\Program Files\Rhino 8\System", 'net48')`; then `import Rhino` and e.g. `Rhino.Geometry.Curve.CreateInterpolatedCurve(pts, 3)`; caveat "you need to explicitly use floating point numbers in Point3d constructor" — [pypi.org/project/rhinoinside](https://pypi.org/project/rhinoinside/); [github.com/mcneel/rhino.inside-cpython](https://github.com/mcneel/rhino.inside-cpython) (50 stars, MIT, `examples/gh-headless` folder present)
- Rhino.Compute "depends on Rhino.Inside, which runs Rhino and Grasshopper inside other 64-bit applications" — [Rhino.Compute FAQ](https://developer.rhino3d.com/guides/compute/compute-faq/)
- No Rhino.Inside for Rhino for Mac "yet", no timeline (search snippet) — [Discourse: Rhino.Inside on macOS](https://discourse.mcneel.com/t/rhino-inside-on-macos/173311)
- McNeel forum thread on using a local MCP server to drive Rhino.Inside.Revit workflows exists (title only) — [Discourse thread 215629](https://discourse.mcneel.com/t/local-mcp-server-to-drive-rhino-inside-revit-workflows-with-ai/215629)

### Inferences
- On Windows, `rhinoinside` is the most direct way for Claude Code to run RhinoCommon from its own Python process (booleans, offsets, `Rhino.FileIO.File3dm` export, `RhinoDoc` import/export of SVG/DXF/STEP when a headless doc is created) without the GUI being interactive; it still consumes the user's Rhino licence seat and requires the Rhino install on that machine.
- On macOS or in a Linux container it is unavailable, full stop.
- The pip package's last release (June 2025) predates Rhino 9 Beta; `load(9, ...)` is advertised but Rhino 9's move to .NET 10 (section 9) may require an update.

### Gaps
- Official documentation on whether Rhino.Inside.CPython can run file import/export plug-ins (SVG, DXF, STEP) headlessly was not found; the README only shows geometry calls.

## 5. Command-line / macro automation of the Rhino desktop app

### Takeaway
Rhino 8 cannot run headless, but it can be launched from a shell with a script and told to exit: Windows `Rhino.exe /runscript="-cmd1 -cmd2 _-Exit" file.3dm` (plus `/nosplash`, `/safemode`, `/notemplate`, `/language=`, `/scheme=`); macOS `open "/Applications/Rhino 8.app" --args -nosplash -runscript "<commands>"`. Inside Rhino, the command line is fully scriptable (hyphen-prefixed commands suppress dialogs; `_-ScriptEditor _R "path.py"` runs a Python 3/C# file; `-GrasshopperPlayer <path.gh>` runs a definition with no GH window). Since Rhino 8.11 a `rhinocode` CLI (Windows and Mac) can list running Rhino instances and send commands or script files to one after `StartScriptServer` has been run in it — the best fit for a terminal agent on the same machine.

### Cited Findings
- General form `Rhino.exe /runscript="-command -secondCommand"`. Switches: `/safemode`, `/nosplash`, `/bigdump`, `/notemplate`, `/language=1034`, `/scheme`, `/runscript`. Render-and-exit example: `"C:\Program Files\Rhinoceros 5 (64-bit)\System\Rhino.exe" /runscript="_SetCurrentRenderPlugIn Rhinoceros _Render _-SaveRenderWindowAs test.jpg _-CloseRenderWindow _-Exit" test.3dm` — [Running Rhino from the Command Line (developer guide, cpp section; example still shows a Rhino 5 path)](https://developer.rhino3d.com/guides/cpp/running-rhino-from-command-line/)
- Rhino 8 Windows help documents `/nosplash`, `/scheme="Name"` (schemes stored as XML under %AppData%) and `/safemode` (no OpenGL/third-party plug-ins) (search snippet) — [Rhino 8 help: Starting Rhino (Windows)](https://docs.mcneel.com/rhino/8/help/en-us/information/startingrhino.htm)
- Rhino 8 Mac help: `open "/Applications/Rhino 8.app" --args -runscript "_Line 0 10,10,10"`; `-nosplash` also skips version checks; longer scripts via `-_RunPythonScript <path>` inside the `-runscript` string; spaces in paths need a backslash (search snippet) — [Rhino 8 help: Starting Rhino (Mac)](https://docs.mcneel.com/rhino/8mac/help/en-us/information/startingrhino.htm)
- Gotcha: `/runscript` was ignored when VS Code passed args as an array; worked when passed as a single string (search snippet) — [Discourse: Starting rhino with runscript from vscode](https://discourse.mcneel.com/t/starting-rhino-with-runscript-from-vscode/205812)
- ScriptEditor macros: `_-ScriptEditor _R "C:\path\to\script.py"`; `_-ScriptEditor _R "HelloWorld.py"` (found via search paths); inline multi-line form `_-ScriptEditor _R (` … `)` with a mandatory language line (`#! python 3`, `#! python 2`, `// #! csharp`); leading `-` = non-interactive, leading `_` = language-neutral; `R` = "Runs given script using the new scripting infrastructure in Rhino 8"; `B` = browse — [ScriptEditor macros guide](https://developer.rhino3d.com/guides/scripting/advanced-scripteditor-macros/)
- RhinoCode CLI: "Rhino3D (>=8.11) ships rhinocode command line utility"; the script server is not started on launch — run `StartScriptServer` in Rhino (or add it to startup commands); add `%PROGRAMFILES%\Rhino 8\System` (Windows) or `/Applications/Rhino 8.app/Contents/Resources/bin` (macOS) to PATH; `rhinocode -V` (example `8.11.24224`); global options `-r, --rhino <RHINO-ID>`, `-v/-d/-t`, `--help`; subcommands `list` (PID, ID, open document, path; `--json`), `command` (e.g. `rhinocode command "_circle 0 0 0 20"`), `script` (`.py`, `.cs`, `.py2`), `project build` (`-bv`, `-bt`, `-bp`; no running Rhino needed) — [RhinoCode Command Line Interface guide](https://developer.rhino3d.com/guides/scripting/advanced-cli/). `rhinocode list` output used to diagnose VS Code connection (search snippet) — [Discourse: VScode to Rhino8 bug](https://discourse.mcneel.com/t/vscode-to-rhino8-bug/183481)
- Third-party notes (community "rhino3d-scripts" skill reference, not McNeel): `rhinocode` connects to a persistent server, so scripts inherit the server's working directory and env, `print()` output is piped back, and extra tokens after the script path are concatenated onto the file URI (pass data via temp files) — [awesome-copilot rhino3d-scripts reference (mirror)](https://git.cynarski.dev/Awesome/awesome-copilot/src/branch/main/skills/rhino3d-scripts/references/macros-and-loading.md) — *unverified, third-party*
- `GrasshopperPlayer` "allows loading and executing a *.gh or *.ghx definition without showing the Grasshopper window"; the scripted form is `-GrasshopperPlayer` and supports system environment variables in paths (e.g. `-_GrasshopperPlayer %USERPROFILE%\...`); missing files are searched in the 3dm's folder and Options > Files > Search Paths (search snippet) — [Rhino 8 help: Grasshopper commands](https://docs.mcneel.com/rhino/8/help/en-us/commands/grasshopper.htm); paths with spaces must be quoted: `-GrasshopperPlayer "C:\blah blah blah\cageMorphPlayer.gh"` (search snippet) — [Discourse: Grasshopper definition to toolbar button](https://discourse.mcneel.com/t/grasshopper-definition-to-toolbar-button/135082)
- Grasshopper Player feature page exists for Rhino 8 — [rhino3d.com Grasshopper Player](https://www.rhino3d.com/features/grasshopper/player/)

### Inferences
- "Headless" in the strict sense is impossible: `/runscript` still launches the full GUI (a window appears, the licence is checked, then the script runs and `_-Exit` closes it). It is fine for batch jobs on a desktop session but will not work on a Windows Server/Linux box without Compute.
- Recommended agent loop on the user's own machine: Rhino running with `StartScriptServer` → agent writes `/tmp/job.py` (`#! python 3` header, `#r:` deps) → `rhinocode --rhino <id> script /tmp/job.py` → script writes results to a known path → agent reads them. Alternative without the CLI: `rhinocode command "_-Import \"C:\maze.svg\" _Enter"` style command strings.
- Because `rhinocode` is bundled on macOS too, the Mac user gets near-parity for *driving the GUI*, even though Compute/Inside are missing.

### Gaps
- The full Rhino 8 Windows "Starting Rhino" help page could not be read; `/runscript` is documented in the developer guide but the search snippet of the Rhino 8 help page did not show it, so I cannot confirm the help page still lists it for Rhino 8 (the developer guide example is Rhino 5-era in its path).
- No official statement on `rhinocode script` argument passing or exit codes; the third-party notes above are the only source.

## 6. Grasshopper: file formats, programmatic authoring, Script components, Player, Hops, external control

### Takeaway
Grasshopper 1 definitions are `.gh` (binary) or `.ghx` (XML), both serialised by the standalone `GH_IO.dll` which does not depend on Rhino; McNeel's own developer (David Rutten) says files can be created/edited with GH_IO but there is no schema and correctness "depends wholly on whether you're supplying the exact right data in the exact right form", so generating definitions from scratch is fragile. In Rhino 8 the single "Script" component (Maths tab) hosts Python 3 or C# (legacy GHPython/C# components still work), Grasshopper Player runs a definition as a Rhino command, and Hops/Rhino.Compute is the only official way to evaluate a definition from outside the app (Windows/Linux server). Rhino 9 ships Grasshopper 2 (own binary format, can import but not export `.gh/.ghx`) alongside GH1.

### Cited Findings
- GH_IO.dll "can open, create, modify and save GH and GHX files"; "GH_IO.dll is a standalone dll that does not depend on Rhino or Grasshopper"; "there is no xml schema that validates a grasshopper file"; whether Grasshopper reads a hand-written file "depends wholly on whether you're supplying the exact right data in the exact right form"; the Grasshopper SDK (inside Rhino) is the easier route; template-based XML is feasible for simple objects (panels, sliders) more than components (David Rutten, old grasshopper3d.com threads; search snippets) — [grasshopper3d.com: ghx format](https://www.grasshopper3d.com/forum/topics/ghx-format); [grasshopper3d.com: ghx files — the technical definition](https://grasshopper3d.com/forum/topics/ghx-files-the-technical-definition)
- `GhToGhx` is a third-party CLI that converts `.gh` to `.ghx` using GH_IO.dll copied from the Rhino install — [bitbucket.org/RILGH/ghtoghx](https://bitbucket.org/RILGH/ghtoghx)
- Rhino 8 Script component: in the Maths tab, Script panel; "since = 8", Windows/Mac; language chosen from the `[ ● ● ● ]` menu (examples Python 3 and C#); zoomable UI with ⊕/⊖ to add/remove parameters; type hints initialise inputs; "completely new and internally different from the legacy GHPython and C# components"; Python 3 uses `#requirements:` (pip), C# uses `#r "nuget: ..."`; Python 2 packages limited to what IronPython supports — [Grasshopper Script component guide](https://developer.rhino3d.com/guides/scripting/scripting-component/)
- Dedicated guides exist for `scripting-gh-python`, `scripting-gh-csharp`, `scripting-gh2-python`, `scripting-gh2-csharp` (the latter two for Grasshopper 2) — [developer-rhino3d-com repo: content/en/guides/scripting](https://github.com/mcneel/developer-rhino3d-com/tree/main/content/en/guides/scripting); GH2 developer guides: `getting-started`, `migrating-components-to-gh2`, `your-first-component-mac/windows` — [content/en/guides/grasshopper2](https://github.com/mcneel/developer-rhino3d-com/tree/main/content/en/guides/grasshopper2)
- Where did the C# component go in Rhino 8? Use the Script component and set its language to C#; Rhino 7 C#/GHPython components can be copy-pasted into Rhino 8 (search snippet) — [Discourse: What happened to C# script component?](https://discourse.mcneel.com/t/what-happened-to-c-script-component/164753)
- Hops on a Rhino.Compute server: Python scripts failed server-side but ran under Remote Desktop; staff suggested the regular Script component set to Python (search snippet) — [Discourse: Rhino 8 Hops/Compute Issues](https://discourse.mcneel.com/t/rhino-8-hops-compute-issues/165649)
- Grasshopper Player: see section 5 ([Rhino 8 help](https://docs.mcneel.com/rhino/8/help/en-us/commands/grasshopper.htm), [feature page](https://www.rhino3d.com/features/grasshopper/player/)); Mac help page for the same commands exists — [Rhino 8 Mac help: Grasshopper](https://docs.mcneel.com/rhino/8mac/help/en-us/commands/grasshopper.htm)
- Hops/Compute as external evaluation: `/io` + `/solve` protocol, headless Rhino+GH server, Windows/Linux only — [How Hops Works](https://developer.rhino3d.com/guides/compute/how-hops-works/); [Compute FAQ](https://developer.rhino3d.com/guides/compute/compute-faq/)
- Grasshopper 2: GH1 `*.gh`/`*.ghx` can be imported into GH2, converted components become "special interop components which rely on Grasshopper 1", native conversion only for sliders, panels, relays, Line 2 Points (early converter) — [Discourse: Grasshopper 2 file upgrader available now](https://discourse.mcneel.com/t/grasshopper-2-file-upgrader-available-now/144047); "You cannot export a grasshopper 2 to the *.ghx file format" — [Discourse: File ghx in G2](https://discourse.mcneel.com/t/file-ghx-in-g2/219944); staff: GH2 "is only really available on Rhino9/Wip/Beta, and it's shipped as part of Rhino9", both GH1 and GH2 will coexist "for the foreseeable future"; interoperability "will always be imperfect" — [Discourse: Rhino Beta Feature: Grasshopper 2 (Beta)](https://discourse.mcneel.com/t/rhino-beta-feature-grasshopper-2-beta/221336?page=2); [Discourse: Grasshopper 2 vs Grasshopper 1](https://discourse.mcneel.com/t/grasshopper-2-vs-grasshopper-1/177596). ### Inferences

## 7. File import/export in Rhino 8 (SVG, DXF, DWG, STEP, IGES, STL, OBJ, 3MF, PDF, AI) and SVG import behaviour

### Takeaway
Rhino 8 natively imports *and* exports 3MF, AI, DXF, PDF, SVG and STEP (plus DWG, IGES, STL, OBJ and dozens more per McNeel's format index) through built-in plug-ins on both Windows and Mac. SVG import offers "Retain grouping", "Group multi curve paths" and "Import filled objects as Curves/Hatches/Trimmed planes"; it maps viewBox units 1:1 to model units (ignoring `width`/`height`), so a millimetre-authored viewBox imports correctly only when the document unit is mm. Layer preservation on SVG import is not documented; on export Rhino 8 emits `<g>` groups for layers/sublayers.

### Cited Findings
- McNeel's Rhino 8 index lists for import: 3MF (*.3mf), Adobe Illustrator (*.ai), AutoCAD Drawing Exchange (*.dxf), Portable Document Format (*.pdf), Scalable Vector Graphics (.svg), STEP (*.stp; *.step); and for export: 3MF, AI, DXF, PDF, SVG, STEP (the English snippet showed 3MF/AI/DXF for export; the zh-tw version of the same page also showed PDF/SVG/STEP). Note: "the Import and Export dialogs only list the file formats that have their plug-ins enabled in Plug-ins options" (search snippets) — [Rhino 8 help: Index of import/export file types](https://docs.mcneel.com/rhino/8/help/en-us/fileio/_index_of_import_export_file_types.htm); marketing format table (3MF, Illustrator, DXF shown for both Windows and Mac) — [rhino3d.com Supported File Formats](https://www.rhino3d.com/features/file-formats/)
- SVG import options: "Retain grouping" imports SVG groups as Rhino groups; "Group multi curve paths" imports a multi-path object as a group; "Import filled objects as" = Curves | Hatches | Trimmed planes (search snippet of the help page) — [Rhino 8 help: SVG import/export](https://docs.mcneel.com/rhino/8/help/en-us/fileio/scalable%20vector%20graphics_svg_import_export.htm)
- Units: an SVG declaring a 100 ft `width` but a small `viewBox` was drawn "at the viewBox numbers in millimeters, ignoring the width and height attributes" — Rhino treats one viewBox unit as one model unit (search snippet) — [Discourse: SVG import doesn't respect width/height](https://discourse.mcneel.com/t/svg-import-doesnt-respect-width-height/124987); point-unit SVGs come in at 1 pt = 0.35277 mm scale (Rhino 6-era) — [Discourse: Scale issue with .svg](https://discourse.mcneel.com/t/scale-issue-with-svg/69643); further unit discussion — [Discourse: SVG scaling units](https://discourse.mcneel.com/t/svg-scaling-units/146492/9)
- Layers on export: a user asked for layered SVG export noting Rhino "is not exporting them in layers"; a separate Rhino 8 SR thread reports Rhino 8 adds extra `<g>` nodes for layers and sublayers compared with Rhino 7 output (search snippets) — [Discourse: Export SVG file with layers](https://discourse.mcneel.com/t/export-svg-file-with-layers/172954); [Discourse: Rhino 8 Service Release Candidate Available (p.5)](https://discourse.mcneel.com/t/rhino-8-service-release-candidate-available/168233?page=5)
- Export without dialog: a long-running request thread exists for scripted SVG export — [Discourse: Export SVG without dialog box](https://discourse.mcneel.com/t/export-svg-without-dialog-box/79676)
- Rhino.Compute on Linux: "Only 3dm files are supported for import and export" (so SVG/DXF/STEP conversion needs Windows Rhino) — [Rhino.Compute on Linux](https://developer.rhino3d.com/guides/compute/compute-linux-getting-started/)

### Inferences
- For the maze app, the safest SVG for Rhino is: `viewBox` in millimetres with `width`/`height` also in `mm`, strokes only (no fills, or fills accepted as "Curves"), one `<g id="layername">` per layer and the "Retain grouping" option on — the groups survive even if layer names do not, and a 5-line Python 3 script in Rhino can then move each group to a layer named after its `id`. Whether `<g id>` names are preserved as Rhino group names is unverified.
- DXF with real layers is likely the more faithful "named layers" carrier into Rhino (and the app already models layers), but I did not research Rhino's DXF layer mapping in this task.
- Scripted (`-_Import` / `-_Export`) use of these formats with pre-set options is possible through the command line, but the SVG options dialog may still appear unless the hyphen form is used; this needs testing.

### Gaps
- I could not read the full SVG help page; export-side options (viewport, text as curves, etc.) and any explicit statement about layer handling on import are missing.
- Whether `<g id>` / `inkscape:label` are used for Rhino group or layer names on import — not documented in anything I found.
- DWG, IGES, STL, OBJ were not individually confirmed from a readable page for Rhino 8 (they appear in McNeel's general format list but the snippet I had named only the six formats above).
